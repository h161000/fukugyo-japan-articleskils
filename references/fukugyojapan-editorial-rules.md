# 副業JAPAN文章・画像キャプションルール

副業JAPANの記事で、同梱`seo-site-skills`に対して追加適用するサイト固有の出力ルール。調査事実や記事構成を変更する規則ではなく、公開MDXの文章表現と画像キャプションを統一する。

## 画像キャプション

本文のMarkdown画像には、直後へ内容を説明するキャプションを1つ置く。

```mdx
![画像に写っている内容を具体的に表すalt](/images/slug-section.webp)

<p style="font-size: 0.75em; color: #666; text-align: center; line-height: 1.5; margin-top: 6px;">画像から直接確認できる事実を簡潔に書きます。</p>
```

- 文字サイズは`0.75em`、文字色は`#666`、中央寄せ、行間は`1.5`、上余白は`6px`で統一する。
- キャプションには画像から直接確認できる事実だけを書き、推測や評価を混ぜない。
- 公開キャプションには`（ユーザー提供画像、YYYY-MM-DD確認）`や`（YYYY-MM-DD確認）`などの出典種別・確認日を付けない。
- 出典URL、ユーザー提供の別、取得日・確認日は削除せず、`images/evidence-webp/README.md`、`research_notes.json`、`facts.md`、`review-report.md`の該当箇所へ残す。
- アイキャッチはfrontmatterから表示するため、本文画像用キャプションの対象外とする。

## 文脈に合う表現

次の表現は使わず、同じ文脈では右側の表現を使う。

| 使用しない表現 | 使用する表現 |
|---|---|
| 一緒に整理できます | 一緒に確認できます |
| 口コミは次の3種類に分けて見ます | 口コミを次の3つの観点から確認します |
| 流れを整理すると、次の順番です | 実際の案内を時系列で並べると、次のとおりです |
| LINEで流しています | LINEで共有しています |

副業情報や実際に続けている副業の話をLINEで届ける説明でも、「そのまま流しています」ではなく「共有しています」と書く。

表現を機械的に差し替えて前後が不自然になる場合は、意味を保った自然な文へ書き直す。読者が確認できる範囲を超えて、専門判断や対応能力を約束しない。

## 筆者の判断を伝える文の組み立て

参加・契約を見送る判断では、文末に「私は見送ります」を後付けせず、「私なら」を先に置き、理由から判断へ自然につなげる。

- NG：高柳大輔のLIGHTNINGは、参加費を払って任せられる範囲が分かりにくく、私は見送ります。
- OK：私なら、高柳大輔のLIGHTNINGは参加費を払って任せられる範囲が分かりにくいので見送ります。

導入・結論・本文・まとめを横断して確認し、同様の表現にも適用する。ただし、すべての意見文を機械的に「私なら」で始めない。事実説明や見出しには適用しない。

## LP・LINE資料の取得者と本文での書き方

ユーザーが「フジが実際に登録して得た情報」と確認したLP情報・LINE画像は、フジ自身の調査・登録後の情報として本文に使用する。

制作担当がユーザーからファイルを受け取ったことを理由に、本文を「第三者から提供された画面の紹介」へ変更しない。

- NG：私自身が登録した体験ではなく、調査用に提供された画面を確認しています。
- OK：私がLINEに登録すると、3本の動画を見た人に参加方法を案内する流れでした。

資料の取得者が未確認の場合は、フジの登録体験と決めつけない。登録の確認だけで、購入・運用・出金・動画視聴まで経験したと書かない。登録日時や資料にないやり取りも補わない。

`facts.md`、`research_notes.json`、画像対応表には、「フジが取得した資料であること」と「ユーザーから制作担当へ提供されたこと」を分けて残す。ユーザーが確認した範囲と出典URL・取得日または不明であることも保持する。

## 装飾の原稿・表示確認

同梱`docs/design-guide.md`の「装飾の適用確認」に従う（正確な参照先は`references/seo-site-skills/docs/design-guide.md`）。

副業JAPANのCSSにマーカーや青文字の設定があることと、記事MDXがそれを使用していることを別々に確認する。MDX内の`<mark>`、青文字のインライン指定または対応クラスを確認した後、375px表示で実際の色・結論の文字サイズ・読みやすさを確認し、結果を`review-report.md`へ記録する。サイト固有の色味を保ち、共通CSSを変えて未指定の原稿を一括装飾しない。

## 納品前Gate

サイトルートで次を実行する。

```bash
python3 /Users/hirototakada/.codex/skills/fukugyojapanarticle/scripts/check_fukugyojapan_editorial.py \
  src/content/articles/<slug>.mdx
```

FAILがあれば公開・commit・push前に修正し、再実行する。機械検査の通過だけで文章の自然さを保証したことにはせず、`critic`と375px表示でも確認する。

次の2項目は機械検査とは別に記事全体を読み、`review-report.md`へ該当文と判定を記録する。

- 判断文の語順：「私なら → 理由 → 判断」になっているか。同型の後付け表現を導入・結論・本文・まとめに残していないか。
- 資料取得者と一人称：ユーザーが確認した取得者と本文の主語が一致しているか。制作担当への提供経路を筆者の未登録と混同せず、確認されていない体験も補っていないか。
