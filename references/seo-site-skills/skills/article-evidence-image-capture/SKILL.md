# 記事証拠画像キャプチャ

記事の文章を先に読み、読者の判断を支える一次資料の該当箇所だけを画像化する。ページ全体を機械的に保存せず、1文が根拠ならその1文だけでもよい。

## 必須成果物

- 赤枠付きWebP画像
- `README.md`の画像対応表
- 各画像の出典URL、対応する本文、挿入位置、alt、キャプション
- 取得できなかったURLと理由
- 本文・画像間の不一致一覧

標準保存先：

```text
<ARTICLEWORK>/images/evidence-webp/
```

## ワークフロー

### 1. 本文から証拠対象を作る

`article-draft.md`またはSWELL HTMLを読み、画像で裏づける主張を抽出する。

優先順位：

1. 料金、返金、解約、クーリングオフ
2. 収益、実績、人数、期間などの数値訴求
3. 商品名、運営会社、責任者、所在地
4. 登録後に初めて表示される条件
5. 本文の結論を左右する公式説明

各画像へ、対応する本文を1文単位で割り当てる。1枚で複数の主張を無理に示さない。

### 2. URLを先に全件確認する

iHub task IDがある場合は、記事作成スキルの方法で登録URLを全件取得してから撮影する。URLごとに次を記録する。

- 表示可
- 404
- DNSエラー
- パスワード・認証が必要
- リダイレクト先
- 記事の証拠として採用／不採用

古いローカル画像だけで判断せず、可能な限り最新ページを再表示する。

### 3. 該当箇所を撮影する

ブラウザ操作は利用可能なBrowserまたはChromeスキルに従う。対象ページの表示後、次の順で範囲を決める。

1. 証拠となる文、表、価格、条件を特定する。
2. 前後の見出しを含めないと意味が変わるか判断する。
3. 意味が保てる最小範囲を撮影する。
4. 文字が小さくなる場合は複数枚へ分割する。

切り出し基準：

- 1文が根拠：見出しまたは項目名＋対象の1文を残す。
- 表の1行が根拠：列見出し＋対象行を残す。
- 料金一覧：文字が読める枚数へ分割する。
- そのままでは細長くなる画像：2分割を第一候補にする。3分割は、2枚では文字が小さい、内容の区切りが3つある、または赤枠箇所が離れている場合に限って検討する。
- 長い開発・商品一覧：WordPressギャラリーで並べる場合は、原則2分割し、左右または上下で並べたときに不自然にならない同一寸法へそろえる。
- 条件が離れている：上下結合またはA/B画像に分け、同一ページの別箇所だとキャプションへ書く。

分割時のルール：

- 分割数は少ないほどよい。まず1枚で可読性を確認し、細長くなる場合は2枚にする。
- 3分割は自動採用せず、2分割後の文字サイズと内容のまとまりを目視して決める。
- 証拠となる1文や1行を分割境界で切らない。
- 見出しと対応文、表の列見出しと対象行を同じ画像へ残す。
- 2分割画像は`04a-○○.webp`、`04b-○○.webp`のように同じ親番号を使う。
- altとキャプションは画像ごとに作り、`前半`、`後半`だけで済ませず、各画像に写っている内容を明記する。
- WordPressギャラリーで横並びにする場合は、画像の幅、高さ、余白、赤枠の太さをそろえる。

固定ヘッダー、追従バナー、チャットボタンが証拠を隠す場合は、スクロール位置を変える。ページ全体キャプチャでレスポンシブ要素が重複する場合は、ビューポート撮影を複数回行う。

### 4. 太い赤枠を付けてWebP化する

`scripts/annotate_evidence.py`を使う。

```bash
python3 scripts/annotate_evidence.py \
  --input /tmp/source.png \
  --output <ARTICLEWORK>/images/evidence-webp/03-price.webp \
  --crop 120,300,1000,700 \
  --box 20,30,980,670 \
  --quality 88
```

- `--crop`：`x,y,width,height`
- `--box`：切り出し後の`x1,y1,x2,y2`。複数指定可
- 赤：`#e60012`
- 枠線：標準12px
- WebP品質：標準88

赤枠は該当文や該当行へ付ける。画像全体を囲うだけでは対象が曖昧になる場合、1文または1行を直接囲う。赤枠で文字を隠さず、上下左右に余白を残す。

### 5. 画像を目視検査する

画像ごとに確認する。

- 本文の主張が実際に写っている。
- 数字、会社名、日付、商品名が本文と一致する。
- 赤枠が別の文を指していない。
- 文字を読める。
- 不要な個人情報が写っていない。
- WebPで保存されている。
- WordPressで横並びにする画像は寸法と分割粒度が合う。
- 縦長画像を分割した場合は、まず2分割で十分な可読性が得られている。3分割にした場合は、その必要性を画像対応表へ記録している。

本文と画像が一致しない場合、画像説明を都合よく変えず、本文の目的に合う画像を撮り直す。最新ページで条件が変わっていた場合は、画像だけでなく`facts.md`と本文の更新候補を報告する。

### 6. 対応表を出力する

`references/output-format.md`の形式で`README.md`を作る。

altは写っている内容を具体的に書く。キャプションは画像から確認できる事実だけを書く。推測、評価、法的断定を混ぜない。

## 禁止事項

- 記事を読まずにLP全体を撮る。
- 証拠がない本文へ雰囲気画像を割り当てる。
- 文字が読めない縦長画像を1枚で納品する。
- 本文にない箇所を赤枠で強調する。
- 赤枠で原文を隠す。
- PNG/JPEGのまま最終納品する。
- 古いページと最新ページを同じ条件として扱う。
- 取得失敗を成功として報告する。

## 完了条件

- 本文の画像候補すべてについて、採用画像または不採用理由がある。
- すべての採用画像がWebPである。
- 各画像に赤枠、出典、対応本文、alt、キャプションがある。
- 本文と画像の数値・条件が一致する。
- WordPressで使う順番と表示形式が明記されている。
