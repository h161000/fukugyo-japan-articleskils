# 記事の型（article types）

執筆前に必ずこのファイルで型を確認する。frontmatter `type` で宣言（省略時 kensho）。
納品ゲート（scripts/check-article.sh）が型別基準で機械チェックする。

## 共通ルール（全型）

- textlint / emダッシュ禁止 / テキストリンクは #0000EE の<a> / 1文1段落
- **見出し(H2/H3)はSEO特化**＝キーワードを前に置いた標準的な見出しにする（例「クオリアの料金｜初期費用と月額の内訳」）。**キャラ口調（「〜したわ」「〜よ」「アタシ」等）や会話調の問いかけ語尾を見出しに入れない**。キャラは本文・吹き出しで出す。見出しは検索意図のKWを満たすのが役目
- 「稼げる」の肯定訴求・「稼げる副業教えます」系の誘導は禁止。LINEは「相談・整理」の切り口
- verdict（危険/要注意/おすすめ/調査中）は kensho 専用
- 崩しルール（全記事同型はAIの指紋）:
  - 書き出しは記事ごとに変える。文言だけでなく**構造ごと**変える（広告引用型/相談実例型/状況提示型/疑問形などを回す）
  - 各型のテンプレは「含める要素のリスト」であって順序固定ではない
  - クロージング・まとめH2の文言の使い回し禁止（直近記事と見比べて逐語一致が無いこと）
  - 例外: ペルソナ仕様の固定決め台詞（挨拶Balloon・締めBalloonの定型文）は毎記事同一でよい（キャラの署名）

## kensho（検証記事）— 基準: 3500字+ / 画像10+(全H2) / 吹き出し8+ / LINE3+

従来どおり SKILL.md の「記事の構成」に従う。verdict 必須。

## matome（ワイド網一覧）— 基準: 4000字+ / 画像5+ / 吹き出し3+ / LINE1+（1〜2箇所まで）

目的: 広いKWの入口（例「AI 副業 種類」「AIでできる仕事」）。ジャンル全体を俯瞰させ、検証記事へ流すハブ。
トーン: 「やってみたい人が損しないための地図」。煽らない。各項目に必ず注意点を添える。

含める要素:
- 導入（誰のための地図か、短く）
- 全項目の俯瞰テーブル（初期費用 / 難易度 / 怪しい勧誘の多さ などの軸）
- 各項目H2: 仕事内容 / 始め方 / 初期費用 / 向き不向き / よくある怪しい勧誘パターン / 関連検証記事リンク（該当記事が無ければ省略）
- 選び方の軸（読者の状況別）
- LINE CTA（「どれにするか迷ったら、申し込む前に聞いて」の切り口）

category は跨ぐ場合付けない（タグで回遊させる）。

## howto（知識・ハウツー）— 基準: 3000字+ / 画像3+ / 吹き出し3+ / LINE1+

目的: 検証記事を読んだ人の「で、どうすれば？」の受け皿（例「AIセミナー 見分け方」「スクール クーリングオフ」「MLMの断り方」）。

含める要素:
- 結論チェックリストを先出し
- 各論（1項目=1H2）
- 実例として検証記事へリンク
- 「迷ったら相談」のLINE CTA

## column（編集長コラム）— 基準: 1500字+ / 画像1+（吹き出し・LINEは任意）

目的: ファン化・キャラ深化。ナターシャの声全開で構成自由。SEO非目的（noindexにはしない）。

## 内部リンク（三角回遊）

- matome → 各項目から検証記事へ
- howto → 実例として検証記事へ
- 関連記事枠は自動で howto/matome が最低1枠混ざる（ArticleLayout実装済み）
- 削除予定のダミー記事（sample-*）にはリンクを張らない
