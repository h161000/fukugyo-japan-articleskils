# SEO・E-E-A-Tチェック

## 目的

書いた記事を push する前に、SEOの基本・構造化データの前提・E-E-A-T を機械的＋人間判断で検査する。

**最優先はLINE登録への導線。** 外部リンクで離脱されたら本末転倒。
権威性は「言及する」ことと「構造化データ」で出す。リンクで出すのは最小限。

## 鉄則

1. **LINE登録 = 最優先**。Google評価のために CV を犠牲にしない
2. **外部リンクは罪。ただし絶対悪ではない**。本当に読者の利益になる時だけ使う
3. **競合ブログ・LP・特商法ページには絶対にリンクを貼らない**
4. **公的機関の言及は事実確認が前提**。形だけ入れるのはNG
5. **判断項目は人間が見る**。スクリプトでパスしたから終わり、にしない

## いつ使うか

- 記事執筆完了後、textlint パス後、git push 前
- 記事内容を大幅修正した時

**例外なし。** 「軽微な修正だから」「時間がないから」でスキップ禁止。

## チェックフロー

```
1. python3 skills/seo-eeat-check/check_eeat.py <記事ファイル>
2. 機械チェックの結果を全件確認
3. 警告/エラーがあれば修正
4. 判断項目を1つずつ目視確認（後述）
5. 全部クリアしたら次のスキル（competitor-check）へ
```

## 機械チェック項目（check_eeat.py が判定）

| # | チェック | エラー条件 |
|---|---|---|
| 1 | frontmatter に verdict 設定済み | 未設定 |
| 2 | frontmatter の category が fukugyo / toushi のいずれか | 未設定 or 不一致 |
| 3 | frontmatter に publishedAt 設定済み | 未設定 |
| 6 | title が 24〜40文字 | 範囲外（原則32字以内・41字以上は check-article.sh でFAIL） |
| 7 | description に疑問形「？」を含まない | `？` を含む |
| 8 | image パスが `/images/` で始まる | 不一致 |
| 9 | 本文に外部リンク（http://, https://）が存在する場合、ホワイトリスト判定 | ブラックリストドメインを検出 |
| 10 | 競合ブログのドメインへのリンクが**1つもない**（最厳格） | 検出したらエラー |
| 11 | 特商法ページ・公式サイト・LP のURLが本文中にない | LPっぽいURLを検出したらエラー |
| 16 | 画像の alt が全て空でない | 空alt を検出 |
| 17 | 「LP」という単語が本文に含まれていない（「広告ページ」「募集ページ」に言い換え） | 検出したらエラー |
| 18 | 「案件」という単語が本文に含まれていない（「副業」「副業情報」に言い換え） | 検出したらエラー |
| 19 | em-dash（——）が含まれていない | 検出したらエラー |
| 20 | `<br>` が含まれていない | 検出したらエラー |

### グレー（人間判断）

- 上記以外のサイトはすべてグレー
- 「読者にとって本当に有益か？」「自社CV経路を妨害しないか？」を都度判定
- **迷ったらリンクにしない**

## 構造化データの前提（ArticleLayout.astro 側で実装）

- `Article` schema（自動生成・既存）
- `BreadcrumbList`（自動生成・既存）
- `Person`（著者マナブ、自動生成・既存）
- `Organization`（運営、BaseLayout.astro で自動生成・既存）
- **`Review` schema**（要追加。frontmatter `verdict` から `ratingValue` 自動マッピング）

`verdict` → `ratingValue` マッピング:

| verdict | ratingValue | 意味 |
|---|---|---|
| `safe` | 5 | 安全 |
| `unknown` | 3 | 判定不能 |
| `warning` | 2 | 注意 |
| `danger` | 1 | 危険 |

frontmatter に optional で追加するフィールド:
- `itemReviewedName`: 検証対象のサービス名（例: "高速資産形成セミナー"）
- `itemReviewedProvider`: 提供元の組織名（例: "株式会社VisionCreator"）

frontmatter にこれらが無い記事は Review schema を出力しない（既存記事を壊さない）。

## 人間判断項目（スクリプトでは検出できない）

| # | 判断項目 | 確認方法 |
|---|---|---|
| H1 | LP引用の内容が改ざんされていないか | スクショと突き合わせ |
| H2 | 装飾なし段落が3つ以上連続していないか | 目視 |
| H3 | 同じ意味の文を連続させていないか（吹き出し→直後本文の重複） | 目視 |
| H4 | 運営者情報に変遷がある案件で、時系列比較が使われているか。情報量が多い案件で「確認済み/未確認」表が使われているか | 目視（該当しない案件はスキップ可） |

## 違反時の対応

| 違反種別 | 対応 |
|---|---|
| ブラックリストドメインへのリンク | 即削除。例外なし |
| LP・特商法・公式サイトのURL検出 | 即削除。本文の文脈もそれに応じて修正 |
| 「LP」「案件」の単語 | 「広告ページ」「副業」に置換 |
| em-dash / `<br>` | 削除して段落分け |
| description が疑問形 | 断定形に書き直す |
| 公的機関言及ゼロ（投資系・副業系） | 該当機関で実際にチェック→1文を本文に追加 |
| 著者プロフリンクゼロ | クロージングや結論セクションに自然に挿入 |

## ループ穴対策

| 言い訳 | 反論 |
|---|---|
| 「軽い修正だから今回はスキップ」 | スキップ禁止。push前は毎回必須 |
| 「機械チェックでパスしたから判断項目はOK」 | 判断項目は別問題。必ず両方やる |
| 「公的機関言及は形だけでいい」 | 事実確認なしの言及はハルシネーション。NG |
| 「外部リンクは1個くらい大丈夫」 | 1個でも離脱すれば負け。本当に必要か常に問う |
| 「競合ブログだけど内容が良いから引用元として」 | 競合への送客は禁止。例外なし |
| 「LPページは出典として書いた方が誠実」 | 検証対象への集客はしない。記事内に書かない |

## Red Flags - STOP and Re-check

- check_eeat.py を実行していない
- 警告が出たまま push しようとしている
- 「とりあえず動く」状態で OK としている
- 公的機関の言及があるのに、実際には機関サイトを見ていない
- 競合ブログのURLを「参考」として書こうとしている

**全部 NG。push 前にやり直し。**
