## 1. サイト基盤（🔴 必須）

### 1-1. titleタグの最適化
- ページごとにユニークなtitleを設定する
- 形式: `記事タイトル | サイト名`
- 文字数: **全角32文字以内が原則**（PCは30字前後、モバイルは40字前後で省略される。41字以上は納品ゲートでFAIL）
- **ターゲットキーワードは先頭に置く。遅くとも先頭20字以内**。Googleは単語の途中では省略しないので、重要KWを末尾に置くと丸ごと消える
- title要素とh1要素では**短い方**がタイトルリンクに採用されやすい
- 詳細（KWの選び方・クリック率の5条件）は `skills/writing-agent/SKILL.md`「タイトルのルール」
- **実装:** Astroのレイアウトコンポーネントでfrontmatterから自動展開

### 1-2. meta description
- 各ページに120〜160文字のユニークな説明文を設定
- 検索結果のスニペットに使われるため、クリック率に直結
- ターゲットキーワードを自然に含める
- **実装:** frontmatterの `description` フィールドからAstroのBaseLayoutで自動出力
- **AI生成時:** 記事本文と一緒にdescriptionも生成させる

### 1-3. canonical URL
- 全ページに `<link rel="canonical" href="...">` を設定
- 重複コンテンツ問題を防ぐ（www有無、末尾スラッシュなど）
- **実装:** Astroの `Astro.url` を使って自動生成

### 1-4. レスポンシブデザイン（モバイル対応）
- Googleはモバイルファーストインデックスを採用
- viewportメタタグ必須: `<meta name="viewport" content="width=device-width, initial-scale=1">`
- タップ領域、フォントサイズ、画像サイズをモバイルに最適化
- **実装:** CSSのメディアクエリ or Tailwind CSS

### 1-5. ページ表示速度（Core Web Vitals）
- LCP（Largest Contentful Paint）: 2.5秒以内
- FID / INP（Interaction to Next Paint）: 200ms以内
- CLS（Cumulative Layout Shift）: 0.1以内
- Astro + Cloudflareの静的配信は表示速度面で非常に有利
- **実装:**
  - 画像のWebP/AVIF変換（Astroの `<Image>` コンポーネント or R2 + Cloudflare Image Resizing）
  - 画像の `width` / `height` 属性を必ず指定（CLS防止）
  - lazy loading: `loading="lazy"` / `decoding="async"`
  - 不要なJavaScriptを排除（Astroの強み）

### 1-6. SSL/HTTPS
- Cloudflareを使えばデフォルトでHTTPS対応
- HTTPからHTTPSへのリダイレクトも設定する

## 2. クローラー向け設定（🔴 必須）

### 2-1. sitemap.xml の自動生成
- 記事ページ + 固定ページのURLをクローラーに伝える
- 記事追加のたびにビルド時に自動更新される
- `lastmod` はビルド日時で自動付与
- **除外対象:** タグページ・カテゴリページ・検索ページ・管理画面（低品質ページやnoindexページをサイトマップに含めない）
- **実装:** `@astrojs/sitemap` インテグレーション（`filter` + `serialize` で制御）

### 2-2. robots.txt
- クロール許可/禁止の指示
- sitemapの場所を記載
- **実装例:**
  ```
  User-agent: *
  Allow: /
  Sitemap: https://example.com/sitemap-index.xml
  ```

### 2-3. Google Search Console 登録
- サイト所有権の確認
- sitemapの送信
- インデックス状況の監視
- **実装:** `<meta name="google-site-verification" content="xxx">` をheadに追加

## 3. 構造化データ・リッチリザルト（🔴 必須）

### 3-1. 構造化データ（JSON-LD）
- 検索結果にリッチリザルト（著者名、公開日、パンくずなど）を表示させる
- **最低限入れるべきスキーマ:**
  - `Article` — 全記事ページに。headline, datePublished, dateModified, author, image
  - `BreadcrumbList` — パンくず用
  - `WebSite` — サイト全体。SearchAction（サイト内検索ボックス用）
- **あると良いスキーマ:**
  - `FAQPage` — FAQ形式の記事に
  - `Organization` or `Person` — 運営者情報に
- **実装:** Astroのレイアウトコンポーネントで `<script type="application/ld+json">` を出力
- ⚠️ **リメディアのサイトでは未実装。ここで差をつけるポイント。**

### 3-2. OGP（Open Graph Protocol）
- SNSでシェアされた時のタイトル・画像・説明文を制御
- **必須タグ:**
  - `og:title` — ページタイトル
  - `og:description` — ページ説明文
  - `og:image` — サムネイル画像（1200×630px推奨）
  - `og:url` — ページURL
  - `og:type` — `article`（記事）or `website`（トップ）
  - `og:site_name` — サイト名
- **Twitter Card:**
  - `twitter:card` — `summary_large_image`
  - `twitter:title` / `twitter:description`
- **実装:** BaseLayoutコンポーネントでfrontmatterから自動展開
- og:imageの自動生成はフェーズ5で対応（Satoriなどを使用）

## 4. サイト構造・ナビゲーション（🟡 重要）

### 4-1. パンくずリスト（Breadcrumb）
- `ホーム > カテゴリ > 記事タイトル` の導線
- Google検索結果にも表示されCTR向上
- BreadcrumbListの構造化データ（JSON-LD）とセットで実装
- **実装:** Astroの共通コンポーネントとして作成

### 4-2. カテゴリ・タグによる分類ページ
- `/category/ai/` — カテゴリ別一覧（大分類）
- `/tag/cloudflare/` — タグ別一覧（小分類）
- トピッククラスター構造を作り、サイトの専門性をGoogleにアピール
- **実装:** Astroの動的ルーティング `[category].astro` / `[tag].astro`

### 4-3. 目次（Table of Contents）の自動生成
- 記事のh2/h3見出しからアンカーリンク付き目次を自動生成
- Google検索結果にジャンプリンクとして表示されることがある → CTR向上
- **実装:** ビルド時にMarkdownのASTを解析して生成

### 4-4. サイト内リンク（内部リンク）の自動挿入
- 記事本文中のキーワードに対して、関連する他の記事へのリンクを自動で張る
- クローラビリティの向上、リンクジュースの分配
- **実装:** ビルド時のremarkプラグインとして実装
- ⚠️ やりすぎるとスパム判定されるので、1記事あたり3〜5本程度に

### 4-5. 関連記事の表示
- 記事下部に同カテゴリ・同タグの記事を3〜5件表示
- 回遊率向上 → 滞在時間増加 → 間接的SEO効果
- **実装:** ビルド時にタグ/カテゴリの一致度でスコアリング

### 4-6. 404ページ（カスタム）
- トップページ・人気記事・検索ボックスへの導線を設置
- 離脱防止とユーザー体験の向上
- **実装:** `src/pages/404.astro`

## 5. 記事ページの要素（🟡 重要）

### 5-1. 見出し構造（h1 → h2 → h3）
- h1は1ページに1つだけ（記事タイトル）
- h2 → h3 の階層を正しく守る（h2の次にh4が来るなどNG）
- 見出しにターゲットキーワードを自然に含める
- **AI生成時:** プロンプトで見出し構造のルールを明示する

### 5-2. 公開日・更新日の表示
- 「公開日」と「更新日」を両方表示
- Googleはフレッシュネス（新鮮さ）を評価する
- 構造化データ（Article）にも `datePublished` / `dateModified` として含める
- **実装:** frontmatterの `pubDate` / `updatedDate` からレイアウトで表示

### 5-3. 読了時間の表示
- 「この記事は約5分で読めます」のような表示
- ユーザーの離脱率を下げる心理効果
- **実装:** 文字数 ÷ 500（日本語の平均読了速度）で自動計算

### 5-4. 著者情報の表示
- 記事に著者名・プロフィールリンクを表示
- E-E-A-Tの「信頼性」に直結
- AIブログでも「運営者として誰が責任を持っているか」を示す
- **実装:** 著者データを定数ファイルで管理し、記事ページで表示

## 7. エンゲージメント・UGC（🟢 推奨）

### 7-1. コメント欄（UGC対策）
- ユーザー生成コンテンツ（UGC）でページの情報量が増える
- エンゲージメントシグナルとしてGoogleに評価される
- スパム対策も必須（ハニーポット、レート制限、NGワードフィルタ）
- **実装:** Cloudflare D1でコメントデータを管理、Workers APIで投稿・取得
- ⚠️ **リメディアのサイトでは未実装。差別化ポイント。**

### 7-2. SNSシェアボタン
- Twitter/X、Facebook、はてなブックマーク、LINE
- シェアされることで被リンク獲得のきっかけ
- OGPが正しく設定されていることが前提
- **実装:** 静的リンクで実装（JSは不要）

### 7-3. サイト内検索
- ユーザビリティ向上 → 滞在時間増加
- WebSite構造化データの `SearchAction` と合わせると、Google検索結果にサイト内検索ボックスが出ることがある
- **実装案:**
  - Pagefind（静的サイト向け、ビルド時にインデックス生成）
  - D1 + Workers API（全文検索API自作）
- ⚠️ **リメディアのサイトでは未実装。差別化ポイント。**

## 9. コンテンツ保護（🟢 推奨）

### 9-1. コピペ防止
- 記事コンテンツの無断転載を防ぐ
- **実装方法（段階的に）:**
  - CSS: `user-select: none;` で選択を無効化
  - JS: 右クリック無効、コピーイベントの抑制
  - ウォーターマーク（透かし）の挿入
- ⚠️ **注意:**
  - 完全な防止は技術的に不可能（ソースコードを見れば取得できる）
  - ユーザー体験を損なう可能性がある（引用したい人も困る）
  - Googleクローラーはコンテンツを読める必要がある
  - 推奨: コピー時に出典元URLを自動挿入するのが良いバランス
    ```
    コピーされたテキスト
    出典: https://example.com/posts/article-title/
    ```

### 9-2. 重複コンテンツ対策
- AI生成記事は他サイトと内容が被りやすいリスクがある
- canonical URLの設定（前述）で自サイトが正規ソースであることを明示
- 独自の視点・データ・事例を加えることで差別化
- Google Search Consoleで重複コンテンツの監視

### 10-3. キャッシュ戦略
- Cloudflareのエッジキャッシュを活用

- **実装:** Cloudflare Cache Rules の設定

## 12. AI記事生成時のSEO品質管理（🔴 必須）

### 12-1. frontmatterのテンプレート
AI生成時に以下の項目をセットで出力させる:
```yaml
---
title: "記事タイトル（全角32文字以内・メインKWを先頭20字以内に）"
description: "meta description（120〜160文字）"
pubDate: 2026-03-26
updatedDate: 2026-03-26
category: "カテゴリ名"
tags: ["タグ1", "タグ2", "タグ3"]
author: "著者名"
slug: "url-friendly-slug"
image: "./hero.webp"
draft: false
---
```

### 12-2. 記事品質のチェック項目
AI生成した記事がSEO要件を満たしているか確認:
- [ ] h2/h3の見出し構造が正しいか
- [ ] 見出しにキーワードが自然に含まれているか
- [ ] 内部リンクの候補となるキーワードがあるか
- [ ] 文字数は十分か（2,000〜5,000文字目安）
- [ ] 独自の視点・具体例が含まれているか
- [ ] meta descriptionが120〜160文字になっているか
- [ ] titleが全角32文字以内で、メインKWが先頭20字以内にあるか

### 12-3. E-E-A-T対策（AI記事で特に重要）
- 一次情報や独自データを加える
- 参考文献・引用元を明記する
- 著者情報を充実させる
- 定期的に記事を更新し、updatedDateを付与する
- AI生成であることを隠す必要はないが、品質を担保する
